The sync implementation processed entity files in directory order
(knowledge → rules → observations) and synced reference edges
inline during entity creation. `insert_edge_skip_fk_violation`
silently dropped edges to not-yet-synced entities.

This meant forward references — entity A references entity B, but
B is processed after A — were lost. Knowledge-to-knowledge
references were particularly affected since WalkDir processes files
in filesystem order, not topological order.

**Impact:** The initial dogfooding knowledge base had 8 reference
edges in frontmatter but only 5 appeared in the DB after indexing.
Graph expansion couldn't reach entities through the missing edges.

**Fix:** Added a second pass in `sync_inner` that re-syncs
reference edges for all entities after the first pass completes.
By that point, all entities exist in the DB, so no edges are
skipped.

**Follow-up fix (2026-09-03 audit):** The second pass only ran
over changed files in incremental sync, so forward references
from unchanged entities to newly created entities were still
dropped. Fixed by collecting all parsed files (not just changed
ones) and running the reference pass over all of them. Also
fixed `sync_single_file` to call `sync_references` so the
`file_save` hook updates edges for single-file changes.
