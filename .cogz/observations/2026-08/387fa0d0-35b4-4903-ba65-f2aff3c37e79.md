`SearchConfig.max_results` in `config.toml` was defined, validated,
serialized, and tested — but never read by any code path. The CLI
hardcoded `--limit` default to 20 via clap's `default_value`
attribute, bypassing the config entirely.

**Why this matters:** A user editing `config.toml` to change
`max_results` would see no effect. The config file is supposed to
be the shared, versioned configuration for the team. Dead config
values erode trust in the config system.

**Fix:** Changed `--limit` to `Option<u32>` (no clap default).
The CLI falls back to `config.search.max_results` when `--limit`
is not specified. The config value is now the default, and the
CLI flag overrides it.

**Lesson:** Every config field must have at least one code path
that reads it. Config fields without readers are dead code that
misleads users. Review config structs against actual usage during
code review.
