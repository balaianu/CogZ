## CogZ v0.6.10

Hotfix — the v0.6.9 linux binaries crash with `SIGILL` (illegal
instruction) on CPUs without AVX2.

### Root cause

GitHub's `ubuntu-latest` runner image (ubuntu-26.04) enables the
`amd64v3` apt architecture variant, so its GCC compiles with
`-march=x86-64-v3` **by default**. cc-rs picks that up for bundled C
dependencies (`libsqlite3-sys`, `libgit2-sys`, `libz-sys`,
`aws-lc-sys`), so their objects carried AVX2+ instructions — e.g. in
SQLite's FTS5 code paths — even though the crate's own Rust code is
built for the x86-64 baseline.

### Fix

- The release build now sets `CFLAGS`/`CXXFLAGS` to
  `-march=x86-64` for the x86_64 linux target, forcing baseline
  codegen for all C objects. Per-file SIMD flags (e.g. aws-lc's
  `-mavx2` dispatch-gated sources) still apply where intended.
- New release gate: an ISA-level canary counts AVX2 integer
  instructions in the produced binary and fails the build if it
  exceeds the small dispatch-stub baseline — v3-compiled code can't
  ship silently again.

### Upgrade notes

Identical to v0.6.9 otherwise — same dependency batch clearing the
five RUSTSEC advisories. **If your machine runs v0.6.9 without
issue, nothing changes.** If `cogz status`/`cogz search` crashed
with "Illegal instruction", this release is the fix — `cogz update`
or reinstall via `install.sh`.
